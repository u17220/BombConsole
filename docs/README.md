# BombConsole ドキュメント

ターミナル上で多人数が同時に対戦するボンバーマン風ゲーム。サーバ(C++)1台に、クライアント(Python / curses)が複数接続する。

- 改善方針(現状の精査と段階的な計画): [`improvement-plan.md`](improvement-plan.md)
- 実装の進捗と確認結果: [`progress.md`](progress.md)
- 図(v1 時点のもの。構成の概観として参照): [`img/`](img/)

## 1. 動かし方

必要なものは、サーバを立てる人が `g++` と `make`(Linux は ncurses の開発パッケージがあればサーバ画面付き、なくても動く)、全員が Python 3(標準ライブラリのみ)。Windows は WSL を使う。端末は UTF-8 で全角文字が表示できるもの(崩れるときは `--ascii`)。

入口は 3 つ。どれも `A_client.py` 1 つで済む。

### 1 人で試す

```bash
git clone <このリポジトリ> && cd BombConsole
python3 client/A_client.py --host --bots 2        # 自分 + ボット 2。3 人そろった時点で自動開始
```

`--host` がサーバを裏で起動し(未ビルドなら `make` も実行)、`--bots 2` がボットを 2 体つなぐ。`q` で抜けるとサーバもボットも止まる。`make play BOTS=2` も同じ。

### 友達とやる(ホスト役)

```bash
python3 client/A_client.py --host --players 3 --bots 1   # 人間 3 + ボット 1 = 4 人そろったら自動開始
python3 client/A_client.py --host                        # 人数を決めない: 全員が r を押したら開始(g で強制開始)
```

ロビーに「others join with: python3 A_client.py 192.168.x.y」と出るので、それを参加者に伝える。サーバのオプションは `--` の後ろに書く(例: `-- --time 90 --rounds 3`)。

### 参加する

```bash
python3 client/A_client.py                  # 同じ LAN のサーバを自動で見つける
python3 client/A_client.py 192.168.1.10     # 見つからなければアドレスを指定(host:port も可)
```

ホストから `client/A_client.py` 1 ファイルを受け取るだけでよい(`curl -O https://raw.githubusercontent.com/<owner>/BombConsole/master/client/A_client.py`)。

### 開始条件の決まり方(`--players` / `--bots` / `--autostart`)

| 指定 | サーバに渡るもの | 開始のタイミング |
|---|---|---|
| `--host --bots 2` | `--autostart 3`(自分 1 + ボット 2) | 3 人目が入った時点で 5 秒のカウントダウン |
| `--host --players 3 --bots 1` | `--autostart 4` | 4 人そろった時点 |
| `--host --players 2` | `--autostart 2` | 2 人目が入った時点 |
| `--host`(= `--players 1`、ボットなし) | なし(合計 1 < 2) | 2 人以上が全員 `r`、またはホストが `g` |
| `--host -- --autostart 5` | `--autostart 5`(後ろが優先) | 5 人そろった時点 |
| `./server/A_server --autostart N` | | N 人そろった時点。`--players` と `--bots` はクライアント側の数え方で、サーバはこの合計しか見ない |

`--players` は自分を含む人間の数(`--host` のときだけ有効)。`--bots` は `--host` なしでも使え、指定または自動発見したサーバへボットを連れていく。ボットはセッションが終わるまで居続ける。autostart の人数に達しなくても、全員が `r` を押せば始まる。

**autostart が効くのは最初の 1 回だけ。** 2 戦目からは、結果画面で `r` を押す(= 準備完了)と始まる。ボットは自動で準備完了になるので、人間が `r` を押すだけでよい。結果画面を読む時間を確保するため、サーバは 2 戦目以降を人数だけでは始めない。

### キー操作

移動 = 矢印 / `WASD` / `hjkl`、ボム = `Space` / `z`、準備完了 = `r`、強制開始 = `g`(ホスト時)、退出 = `q`(ラウンド中は 1 秒以内に 2 回)。`t` で危険マスの予告表示を切り替えられる(既定オフ)。

### クライアントのオプション

| オプション | 内容 |
|---|---|
| `host[:port]` | 接続先。省略時は LAN 自動発見(UDP ブロードキャスト、ポート 10001)。環境変数 `BOMBCONSOLE_SERVER=host:port` でも可 |
| `--host` | サーバ(`server/A_server --no-ui`)を子プロセスで起動して 127.0.0.1 に接続。サーバの出力はリポジトリ直下の `.bombconsole-server.log` |
| `--players N` / `--bots N` | 上の表のとおり |
| `-- ...` | 以降はサーバの引数(`--port` があればその値に接続) |
| `--name 名前` | 名前(既定: 環境変数 `BOMBCONSOLE_NAME` > ログインユーザー名)。同名はサーバが `(2)` を付ける |
| `--ascii` | ASCII 文字だけで描く(1 マス 2 桁)。既定は全角(1 マス 3 桁) |
| `--threat` | 危険マス(今あるボムの炎が届くマス)の予告表示をオンで始める。既定はオフ。ラウンド中に `t` で切替 |

画面: 上 1 行が HUD(名前、ボム 残/最大、火力、速度段階、生存者数、残り時間、サドンデス)。マップは v1 と同じ見た目で、1 マス 3 桁。

| マス | 全角モード | `--ascii`(1 マス 2 桁) |
|---|---|---|
| 自分 / 他のプレイヤー | `自` / `敵`(プレイヤーごとの色) | `1`〜`8`(自分は反転) |
| 死亡中 | `死` | `x` |
| ブロック / 壊せる岩 | `■` / `岩` | `#` / `+` |
| ボム | `爆*`: `爆` は青、導火線 `*` は黄色で `*` `+` と揺れ、残り 1 秒を切ると赤の太字 | `o`(残り 1 秒を切ると赤) |
| 炎 | `炎`(赤) | `*` |
| アイテム | `力` = 火力+(黒字に黄背景)、`玉` = ボム+(黒字にシアン背景)、`速` = 速度+(黒字に緑背景) | `F` / `B` / `S`(同じ背景色) |

アイテムは「光っている」ように背景色で目立たせ、炎と混同しないよう赤系は使わない。マップの下に凡例として各プレイヤーの名前をその色で出し(自分は反転、死亡は `x`)、その下にアイテムの対応(`力=火力+  玉=ボム+  速=速度+`)を実際の色で常時表示する。

### サーバだけを立てる(上級者向け、常駐させる場合)

`ssh` 先や教室の 1 台に置いておく場合は、サーバ単体で起動する(`--host` が裏でやっていることと同じ)。

```bash
make                               # server/A_server ができる(ncurses の有無は makefile が自動判定)
./server/A_server                  # ncurses の観戦画面付き(make run でも同じ)
./server/A_server --no-ui          # 画面なし。ssh 先や tmux に置いておける
./server/A_server --help           # 全オプション
```

- 起動すると待受ポートと、クライアントの起動コマンド例を表示する。
- クライアントが接続すると名前一覧に出る。**2 人以上が全員 `r`(準備完了)を押すと 5 秒後に開始**する(`--autostart N` なら N 人そろった時点)。サーバ画面の `g` で強制開始、`q` で終了(`--no-ui` のときは標準入力に `g` / `q` の行を入れても同じ)。
- ラウンドが終わると結果を全員に送り、接続を閉じずにロビーに戻る。クライアントは `r` でもう 1 戦できる。
- パラメータは `--key value` と設定ファイル `server.conf`(`key = value`、1 行 1 項目、`#` 以降はコメント)で変えられる。引数が優先。例:

```
# server.conf
port = 10001
rounds = 3
fuse = 2.5
```

| オプション | 既定 | 内容 |
|---|---|---|
| `--port N` | 10001 | TCP ポート。0 で空きポート |
| `--discovery N` | 10001 | 自動発見に応答する UDP ポート。0 で無効 |
| `--no-ui` | | ncurses 画面を使わず標準出力にログを出す |
| `--name S` | ホスト名 | クライアントに見せるサーバ名 |
| `--conf FILE` | server.conf | 設定ファイル |
| `--seed N` | 0(ランダム) | 乱数の種(再現テスト用) |
| `--log FILE` | | ゲームのイベントを JSON 行で追記(`tools/stats.py` で集計) |
| `--rounds N` | 1 | 1 セッションのラウンド数 |
| `--countdown N` | 5 | 全員準備完了から開始までの秒数 |
| `--min-players N` / `--max-players N` | 2 / 8 | 開始に必要な人数 / 1 ラウンドの上限(超えた分は観戦) |
| `--autostart N` | 0 | N 人そろったら準備完了を待たずに開始(最初のラウンドだけ。以降は全員 `r`) |
| `--tick MS` | 50 | tick の長さ |
| `--fuse S` / `--fire S` / `--dying S` | 2.5 / 0.5 / 1.0 | 導火線 / 炎の持続 / 死亡演出(秒) |
| `--bombs N` / `--power N` / `--speed N` | 1 / 2 / 5 | 初期の同時ボム数 / 炎の長さ / 1 マスに要する tick 数 |
| `--bombs-max N` / `--power-max N` / `--speed-min N` | 6 / 8 / 3 | アイテムで伸びる上限 |
| `--time S` | 120 | ラウンドの制限時間(0 でなし) |
| `--sudden-death S` / `--sd-rate N` | 30 / 4 | 終了の何秒前から壁が迫るか / 1 秒に何マス閉じるか(0 でなし) |
| `--soft PCT` / `--soft-2p PCT` | 60 / (soft−10) | ソフトブロックの密度(3 人以上 / 2 人) |
| `--item PCT` | 35 | ソフトブロックを壊したときにアイテムが出る確率 |
| `--item-fire N --item-bomb N --item-speed N` | 45 : 35 : 20 | アイテムの種類の比率 |
| `--legacy-map` | | v1 の正方形マップ(`4*ceil(sqrt(n))-1`)を使う |

### ボット

```bash
python3 client/bot.py <サーバ> [--name NAME] [--rounds N]     # --rounds 0 でサーバが閉じるまで居続ける
```

curses を使わない簡単なクライアント。接続して準備完了を送り、毎 tick の `state` から「危険マスにいれば逃げる → アイテムがあれば取りに行く → 敵かソフトブロックが炎の届く範囲にあり、逃げ道があればボムを置く → 目標へ寄る(サドンデス中は中央へ)」の順で判断する。1 人で試すときの相手、ヘッドレスの自動対戦(`make check`、バランスの集計)に使う。プロトコルの最小実装例でもある。強さの調整は目的にしない。

### 同一マシンで別々に起動して試す

```bash
make
./server/A_server                      # ターミナル 1
python3 client/A_client.py             # ターミナル 2(r を押す)
python3 client/bot.py                  # ターミナル 3(自動で準備完了)
```

1 つのターミナルで済ませるなら `python3 client/A_client.py --host --bots 1`。

### イベントログと集計(バランス調整)

```bash
./server/A_server --log events.jsonl
python3 tools/stats.py events.jsonl
```

ログは 1 行 1 JSON で、`ev` が `start`(人数、席、座標、seed)/ `bomb` / `explode` / `item` / `kill` / `suicide` / `suddendeath` / `disconnect` / `timeout` / `result`(`result` メッセージと同じ内容)。`stats.py` は [`improvement-plan.md`](improvement-plan.md) 1 節の目標値(ラウンド長の中央値、15 秒以内の決着率、自爆率、勝者のアイテム数、席ごとの勝率)を出す。パラメータを変えては数字を見る、を回すための道具。

### 自動テスト

```bash
make check
```

サーバを `--no-ui --port 0 --countdown 0 --time 60` で起動し、ボットを 2 体つないで 1 ラウンドを完走させ、両者が同じ結果を受け取ることを確認する(`tools/check.py`)。`make check ARGS="--soft 60"` のようにサーバの引数を足せる。

```
BombConsole/
├── makefile                 make / make run / make play / make check
├── server/                  C++11 サーバ
│   ├── server.cpp           main: Session(ロビー → ラウンド → 結果 → ロビー)
│   ├── Game.{hpp,cpp}       1 ラウンドのルール(マップ、プレイヤー、ボム、炎、順位)
│   ├── ServerClient.{hpp,cpp}  TCP サーバ。受信スレッドが行とイベントをキューに積む
│   ├── Config.{hpp,cpp}     引数と server.conf
│   ├── Discovery.{hpp,cpp}  UDP の自動発見応答と LAN アドレスの列挙
│   ├── Ui.{hpp,cpp}         サーバ画面(ncurses)。NO_CURSES / --no-ui では標準出力
│   ├── Json.hpp             JSON の書き出し(パーサは持たない)
│   ├── ncurses_probe.cpp    makefile の ncurses 検出用
│   └── makefile
├── client/
│   ├── A_client.py          curses クライアント(1 ファイル、標準ライブラリのみ)
│   ├── bot.py               ボット
│   └── legacy/              プロトコル v1 のサンプル(動かない。課題用の資料)
├── tools/
│   ├── check.py             自動テスト
│   └── stats.py             イベントログの集計
└── docs/
```

### サーバのスレッド

| スレッド | 役割 |
|---|---|
| main | 50 ms ごとに「ネットワークイベントの処理 → `Game::tick` → 状態の全員配信 → 画面描画」を `sleep_until` で刻む。ゲームの状態を触るのはこのスレッドだけ |
| accept | `accept` して `Client` を作り、CONNECT イベントを積む |
| discovery | UDP で `BOMBCONSOLE?` を受けたら `BOMBCONSOLE <TCPポート> <サーバ名>` を返す |
| Client × N | `read` して改行で区切り、LINE イベントを積む。切断で DISCONNECT を積んで終了 |

ロビー中も同じ周期で回り、`READY` の集計とカウントダウンをする。サーバ画面の `getch` は非ブロッキングで、周期には関与しない。

## 3. 通信プロトコル v2

TCP、既定ポート 10001。**1 行 1 メッセージ**(改行区切り)。クライアント → サーバは空白区切りのテキスト、サーバ → クライアントは JSON。`nc サーバ 10001` でつないで `HELLO 1 名前` と打つだけで盤面が文字として流れてくる。

### クライアント → サーバ

| メッセージ | 意味 |
|---|---|
| `HELLO 1 <名前>` | 参加(プロトコル版 1)。名前は行末まで(空白可、最大 24 バイト、制御文字は除去) |
| `READY 1` / `READY 0` | 準備完了 / 取り消し(ロビーでのみ有効) |
| `IN <U\|D\|L\|R\|-> <0\|1>` | 入力。方向(なしは `-`)とボム設置。キーを押したときに送る。例: `IN R 0`、`IN - 1` |
| `BYE` | 退出 |

### サーバ → クライアント

| `t` | いつ | 内容 |
|---|---|---|
| `welcome` | HELLO の応答 | `{"t":"welcome","you":0,"proto":1,"name":"hiira","server":"host"}`。`you` が自分の番号(0〜7)、`name` は重複処理後の名前 |
| `lobby` | ロビーで変化があるたび | `{"t":"lobby","players":[{"id":0,"name":"hiira","ready":true,"score":0}],"countdown":5,"min":2,"max":8,"round":1,"rounds":1}`。`countdown` は未開始なら `null` |
| `start` | ラウンド開始 | `{"t":"start","round":1,"rounds":1,"w":7,"h":7,"tick_ms":50,"time":0,"players":[{"id":0,"name":"hiira","x":1,"y":1}]}` |
| `state` | 毎 tick | 下記 |
| `result` | ラウンド終了 | 下記 |
| `end` | セッション終了(全ラウンド終了、またはサーバ終了) | `{"t":"end","rounds":1,"score":[{"id":0,"name":"hiira","score":1,"kills":2}]}`。サーバ終了時は `{"t":"end","msg":"server closed"}` |
| `error` | 不正な HELLO | `{"t":"error","msg":"..."}` のあと切断 |

`state`:

```json
{"t":"state","tick":123,"left":97.5,"sd":false,
 "map":["#######","#1   2#","# # # #","#  o  #","# # # #","#   * #","#######"],
 "players":[{"id":0,"x":1,"y":1,"st":"alive","bombs":3,"maxb":4,"fire":3,"spd":1,"kills":0}],
 "bombs":[{"x":3,"y":3,"fuse":1.2,"owner":0}],
 "threat":[".......",".......","...!...",".!!!!!.","...!...",".......","......."]}
```

- `map` は 1 行 1 文字列、1 マス 1 文字。`#` ハードブロック、`+` ソフトブロック、`o` ボム、`*` 炎、`1`〜`8` 生存プレイヤー(番号 = `id`+1)、`x` 死亡演出中、`F`/`B`/`S` アイテム、空白は何もなし。重なるときは 炎 > プレイヤー > ボム > アイテム > ブロック の優先で 1 文字にする。正確な座標は `players` / `bombs` にある。
- `left` は残り秒(制限時間なしなら -1)。`sd` はサドンデス中なら `true`。`st` は `alive` / `dying` / `dead`。`bombs` は今置ける数、`fire` は炎の長さ、`spd` は速度段階(1〜3)。
- `threat` はボムか炎があるときだけ付く。`map` と同じ形で、今あるボムが爆発したときに炎が届くマス(燃えているマスを含む)が `!`、それ以外は `.`。クライアントの危険マス表示(既定オフ、`t` / `--threat`)に使う。

`result`:

```json
{"t":"result","round":1,"rounds":1,"ticks":115,"timeout":false,
 "ranking":[{"id":1,"name":"bob","rank":1,"kills":1,"items":0,"cause":"alive","by":-1,"score":0},
            {"id":0,"name":"alice","rank":2,"kills":0,"items":0,"cause":"killed","by":1,"score":0}],
 "events":[{"type":"kill","tick":110,"killer":1,"victim":0}]}
```

`cause` は `alive`(生存)/ `killed`(`by` に倒した相手)/ `suicide`(自爆)/ `suddendeath` / `disconnect` / `timeout`。同じ tick に死んだ場合は同順位。

### ロビーと観戦

- 接続直後に `HELLO` を送ると `welcome` と `lobby` が返る。`lobby` はロビーの変化(参加、退出、準備、カウントダウンの秒)ごとに全員へ送る。
- `min-players` 人以上が全員 `READY 1` になるとカウントダウンが始まり、誰かが取り消すか退出すると止まる。
- ラウンド中に `HELLO` した接続は観戦者になる(`start` と毎 tick の `state` は届くが `IN` は無視)。次のロビーから参加者になる。
- ラウンド中の切断は死亡(`disconnect`)扱い。ロビー中の切断は一覧から消える。

## 4. ゲームの仕組み(サーバ)

### 4.1 tick

50 ms(20 Hz)。`Game::tick` は次の順で進める。

1. 入力の反映: ボム要求があれば置く(自分のマスにボムがなく、置ける数が残っていれば)。方向入力があり、移動のクールダウン(`speed` tick)が切れていれば 1 マス進める。**1 回の入力で 1 マス**(押しっぱなしは OS のキーリピートで入力が繰り返されるだけ)。ブロックとボムのマスには入れない。自分が置いたボムのマスからは出られる。
2. ボム: 導火線を減らし、0 になったら爆発。炎は爆心から十字に `power` マス。ハードブロックの手前で止まり、ソフトブロック・アイテム・ボムのマスは含めて止まる。ボムに当たると**同じ tick で**誘爆する。炎のマスには「持ち主」が記録される(先に来た炎が優先)。
3. 炎の上にいる生存者は死亡演出(`dying`、1 秒)に入る。持ち主が自分なら自爆、他人ならその人のキル。ハードブロックのマスにいる場合も死ぬ(サドンデス用)。
4. 生存者が 1 人以下になったら 1 秒後にラウンド終了。制限時間(`--time`)があれば、時間切れでも終了(生存者は同順位)。

### 4.2 ルール(段階 1)

| 項目 | 値 |
|---|---|
| マップ | 人数別プリセット。2 人 13×11、3〜4 人 15×13、5〜6 人 19×15、7〜8 人 21×17。外周と偶数座標にハードブロック |
| 初期位置 | 四隅(2 人は対角)。5 人目からは各辺の中央。初期位置とその隣にはソフトブロックを置かない |
| ソフトブロック | 可動マスの 60%(2 人は 50%)。炎で壊れ、35% でアイテムが出る(火力 45 : ボム 35 : 速度 20)。アイテムは炎で消える |
| 初期能力 → 上限 | 同時ボム 1 → 6、炎の長さ 2 → 8、速度 5 tick/マス → 3 tick/マス(4 → 6.7 マス/秒) |
| 導火線 / 炎の持続 / 死亡演出 | 2.5 秒 / 0.5 秒 / 1.0 秒 |
| 制限時間 | 120 秒。残り 30 秒からサドンデス: 可動マスの外周から時計回り(開始点はランダム)に 1 秒 4 マスずつハードブロックになる。下敷きになったプレイヤーは死亡、ボムは消える(持ち主に返る)。時間切れは生存者全員が同順位 |
| キル | 炎に持ち主がある。誘爆しても各ボムの持ち主に帰属。自分の炎なら自爆(得点なし) |

`state` の `sd` が `true` のあいだサドンデス中。

### 4.3 順位

死亡 tick の降順(生存者が 1 位)。同じ tick に死んだ場合は同順位。`--rounds` が 2 以上のときは 1 位に 1 点、全ラウンド終了で `end` に合計を入れる。

## 5. クライアント(`A_client.py`)

1. 接続先を決めて(引数、自動発見、または `--host` で起動した 127.0.0.1 の子プロセス)、`HELLO 1 名前` を送る。受信スレッドが JSON 行を読んでキューに積む。`--host` のときは `Host` クラスが `server/A_server --no-ui` と `bot.py` を `subprocess` で起動し、ログの `listening on TCP port` 行でポートを確認してから接続する。終了時は SIGTERM → 3 秒 → SIGKILL で止める。
2. `curses.wrapper` の中で 20 ms ごとにキューを空にして画面を更新し、キーを読む。例外や `Ctrl-C` でも端末は復元される。
3. 画面は 3 種類。ロビー(名前一覧、準備状態、カウントダウン)、ゲーム(上 1 行 HUD、マップ、下に番号と名前の凡例)、結果(順位と死因)。結果画面は何かキーを押すとロビーに戻る。
4. 端末がマップに足りない場合は「terminal too small」と必要サイズを出す。リサイズで再描画する。

全角モードの文字(v1 と同じ): `■` ハード、`岩` ソフト、`爆*` ボム(導火線付き)、`炎`、`自` / `敵` プレイヤー(色で区別)、`死`、`力`/`玉`/`速` アイテム(背景色付き)。1 マスは 3 桁。`■` は East Asian Ambiguous 幅で端末により 1 桁か 2 桁かが変わるため、起動時に curses で `■` を書いてカーソルの進みを測り、1 桁なら空白 2 つ、2 桁なら空白 1 つを後ろに付けて 3 桁に揃える。他の文字は Wide(2 桁)で安定している。

## 6. macOS で直した点(v1 から引き継ぎ)

- `-lncursesw` が macOS にないため `-lncurses` を使う。v2 では makefile が `ncursesw` → `ncurses` の順に試し、どちらもなければ `NO_CURSES` でビルドする。
- `sockaddr_in` は `memset` で 0 埋めしてから使う(BSD 系の `sin_len`)。
