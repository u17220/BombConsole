# 実装の進捗

方針: [`improvement-plan.md`](improvement-plan.md) 6 節の段階 0 → 3 の順。各段階の終わりで `make check`(ヘッドレスのサーバ + ボット 2 体で 1 ラウンド完走)が通ることを確認する。

## 段階 0: 土台(2026-10-10)

### やったこと

- プロトコル v2(5.1 節): サーバ → クライアントは改行区切り JSON のプッシュ、クライアント → サーバは `HELLO` / `READY` / `IN` / `BYE` のテキスト行。マップは 1 行 1 文字列。
- サーバの構造を書き直した。受信スレッドは行をキューに積むだけで、main スレッドが 50 ms(20 Hz)の tick ごとに「イベント処理 → `Game::tick` → 全員へ `state` 配信 → 画面描画」を `sleep_until` で刻む。tick はサーバ画面の `getch` に依存しない。
- 移動のサーバ権威化と速度制御(3.6 節): クライアントは方向とボムだけを送り、サーバが `speed` tick ごとに 1 マス進める。1 入力 1 マス。

- ヘッドレス(5.3 節): `--no-ui`。makefile が ncurses の有無を自動判定し、なければ `NO_CURSES` でビルド。
- ロビー: 名前一覧、`READY` と全員準備完了からのカウントダウン、`g` で強制開始。ラウンド終了後はロビーに戻る(再起動不要)。名前の重複は `(2)` を付ける。ラウンド中の接続は観戦。
- キルの帰属(炎の持ち主)、同 tick 死亡は同順位、死因付きの結果、`--time` による制限時間。ルールの数値は v1 のまま(7×7、ボム 4、炎 3、導火線 2 秒、炎 1 秒)。

- `client/bot.py`(5.6 節の最小版)、`tools/check.py`、トップレベル `makefile`(`make` / `make run` / `make check`)。
- `task1〜3_sample.py` と `keysend.py` を `client/legacy/` に移動。旧オブジェクトモデル用の `test*.cpp` / `sctest.cpp` は削除(新しい構造では使えないため)。

## 追加: ワンコマンド起動(2026-10-11)

### やったこと

- `A_client.py --host [--players N] [--bots N] [-- サーバの引数...]`。`--host` は `server/A_server --no-ui` を子プロセスで起動(バイナリがなければリポジトリ直下で `make`、それでも無ければエラー)、ログは `.bombconsole-server.log`(`.gitignore` 済み)。`--bots N` は `client/bot.py` を `--rounds 0`(セッション終了まで居続ける)で N 体起動し、`--host` なしでも指定・自動発見したサーバへ連れていく。`--players N`(既定 1、`--host` 時のみ)は `--autostart (players + bots)` をサーバに渡す。合計が 2 未満なら autostart を渡さず、ロビーに「everyone presses r (or g here)」と出す。`--host` なしの `--players` と `--` は警告して無視。
- ホスト中のロビーに「others join with: python3 A_client.py 192.168.x.y」(サーバのログの `clients:` 行から取得)、自動開始の条件、サーバ停止の表示。`g` でサーバの標準入力に `g` 行を送って強制開始。
- 終了処理: `q`、Ctrl-C、例外、サーバ切断のいずれでも `finally` で全子プロセスに SIGTERM → 3 秒待って SIGKILL。子プロセスは `start_new_session=True` で端末の Ctrl-C から切り離し、クライアントが責任を持って止める。サーバは SIGTERM で `g_stop` が立ち、結果の送信と `end` の配信をしてから終了する(既存の挙動)。
- `make play BOTS=2`。README の「動かし方」を「1 人で試す / 友達とやる / 参加する」の 3 入口から始め、`--players` / `--bots` / `--autostart` の関係を表にした。サーバ単体の起動は「上級者向け」として後ろに回した。

### 確認方法と結果

- pty 上で `--host --bots 2 -- --time 30 --countdown 1` を起動: ロビーに自動開始の条件と参加コマンドが出て、3 人そろった時点でカウントダウン → 1 ラウンド完走 → 結果画面 → `q` で終了コード 0。1 秒後の `pgrep` で `A_server` / `bot.py` は残っていない。
- `--host --players 2 --bots 1`: 1 人目(自分 + ボット 1 = 2)では開始せず待ち状態。手で `bot.py` を 1 つ足すと 3 人そろって「starting in 1 s」→ ラウンド開始。終了後にプロセスは残らない。
- `--host --bots 1 -- --countdown 30`: カウントダウン中に `g` を押すと即開始(「force start sent」)。ラウンド中に SIGINT(Ctrl-C 相当)を送ると、クライアントは終了し、サーバとボットも残らない。サーバのログには結果まで記録されている。
- `make check` → `CHECK OK`。

### 未解決の点

- `--host` はリポジトリの中から実行する前提(`server/` が必要)。`A_client.py` だけを配った人は「参加する」入口のみ。
- サーバが起動済みでポート 10001 が使用中のときは、`--host` は「the server did not start」とログを表示して終了する。別ポートで立てるには `-- --port 10002`。
- カウントダウン(既定 5 秒)は `--host --bots N` でも入る。短くしたければ `-- --countdown 1`。

## 追加: autostart の範囲とプロセスの後始末(2026-10-11)

### やったこと

- `--autostart` はサーバ起動後の最初のラウンドにだけ効くようにした。それまでは、`--rounds 1` のセッションが終わってロビーに戻ると接続数が条件を満たしたままで、人間が何もしなくても次が始まっていた。2 戦目からは全員の `READY`(ボットは自動、人間は結果画面で `r`)で開始する。結果画面は「r: play again   q: quit」と、準備完了済みの名前を出す。
- クライアントに SIGTERM / SIGHUP のハンドラを登録し、`SystemExit` を投げて `finally` の子プロセス停止(SIGTERM → 3 秒 → SIGKILL)を必ず通す。`getch` は 20 ms タイムアウトで戻るので curses 画面中でも効く。
- 二重の保険として、子プロセスの標準入力をクライアントが持つパイプにした。サーバ(`--no-ui`)は標準入力がパイプ(またはソケット)で EOF になったら `q` 相当で終了する(`/dev/null` やファイルの EOF では終了しない。`make check` は `/dev/null` を渡している)。ボットは標準入力が FIFO のときだけ監視スレッドを立て、EOF で `os._exit(0)`。これでクライアントが SIGKILL で消えても、端末ごと消えても、サーバとボットは残らない。`Host.stop` もまずパイプを閉じてから SIGTERM を送る。

### 確認方法と結果

- pty で `--host --bots 2 -- --time 20 --countdown 1 --port 10077 --discovery 0`: 結果画面で 10 秒放置してもサーバログの `round 1 start` は 1 回のまま。`r` を押すと「starting in 1 s」→ 2 戦目開始(`round 1 start` が 2 回)。`q` で全プロセス終了。
- pty で `--host --bots 2` をゲーム中に (a) `kill -TERM`、(b) `kill -HUP`、(c) `kill -KILL`: クライアントは即終了(終了コード 143 / 129 / シグナル 9)、`A_server` と `bot.py` はいずれも 0.3 秒以内に `pgrep` から消えた。
- `make check` → `CHECK OK`。

### 未解決の点

- ncurses 画面付きのサーバ(`--no-ui` なし)は標準入力の EOF では終了しない(`getch` 経由のため)。`--host` は常に `--no-ui` なので影響はない。

## 追加: ボムとアイテムの見た目(2026-10-11)

### やったこと(全角モード中心)

- ボムを v1 と同じ `爆*` にした。`爆` は青、導火線 `*` は黄色で、4 tick(0.2 秒)ごとに `*` と `+` を切り替えて燃えている感じを出す。残り 1 秒未満は導火線だけ赤の太字(`爆` の色は変えない)。A_BLINK は使わない(端末依存で、揺れで代替)。ASCII モードは `o` のまま(1 秒未満で赤)。
- アイテムは「取るもの」に見えるように、黒文字 + 明るい背景にした: 火力+ `力`(黄背景)、ボム+ `玉`(シアン背景)、速度+ `速`(緑背景)。赤系は炎と混同するので使わない。ASCII の `F` / `B` / `S` にも同じ背景を付けた。
- プレイヤー凡例の下に `力=火力+  玉=ボム+  速=速度+` を実際の色で常時表示(ASCII は `F=fire+ B=bomb+ S=speed+`)。全角文字の幅を数えて間隔を揃える。必要行数を 1 行増やした(マップ高さ + 4)。
- README の文字の表を追従。

### 確認方法と結果

- pty(80×24、`LANG=ja_JP.UTF-8`)で `--host --bots 1 -- --item 100` を起動し、簡易 VT100 モデルで画面を展開。ボムを置いたマスが `爆*`、1.4 秒後のフレームでは導火線が `+` に変わっていること、マップ上に `力` が出ていること、凡例が `力=火力+  玉=ボム+  速=速度+` と等間隔で並ぶこと、全マスが 3 桁の境界に揃うことを確認。色は VT100 モデルでは見えないため、色の最終判断は実機に委ねる(文字は実機で見比べて変えてよい)。
- `q` で終了し、サーバとボットは残らない。`make check` → `CHECK OK`。

## 演出とルールの調整(2026-10-14)

- 勝負が決まったとき、結果画面でマップを消さずに、その時点のマップを止めて残すようにした(クライアントだけの変更、プロトコルは同じ)。生存者が 1 人以下になった最初の `state` を保存し、以降の `state` は画面に反映しない。決着から結果が届くまでの約 1 秒は「ROUND OVER」を出して止まる。結果画面では、そのマップの下にランキングを出し、画面が低ければマップの右、それも入らなければ従来どおり順位だけにする。時間切れ(死者なし)は最後の `state` をそのまま使う。
- サドンデス中に、持ち主のいない爆弾が空から降るようにした(`--sd-bomb`、既定 1 秒に 0.5 個、0 でなし)。壁が迫り始めた tick から、一定間隔でランダムな空きマス(ブロックと既存のボムを除く)に、通常のボムと同じ導火線と火力で置く。持ち主がいないので、炎で死ぬと死因は新しい `skybomb`(ログのイベントも `skybomb`)。プロトコルの `cause` に値が 1 つ増えただけで、他は同じ。`bot.py` は持ち主の火力を `.get(owner, 2)` で引くので `owner: -1` でも動く。

### 確認方法と結果

- `make check` は通った。壁をほとんど動かさず `--sd-bomb 3` にして操作しない 2 人をつなぐと、持ち主なしのボムが同時に最大 8 個出て、片方が `skybomb` で死に、`result` に `cause: skybomb` と `skybomb` イベントが入った。
